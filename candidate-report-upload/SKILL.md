# 候选人推荐报告（通用模板）

把一份简历变成客户愿意往下看的推荐报告。结构和版式是固定的，内容才是要写的。

核心文件：`scripts/report.py`（python-docx，从零构建 docx，不依赖任何二进制模板）。

## 〇、开工第一问：有没有你们公司自己的模板

第一次给某个用户出报告时，先问这一句：

> 你们公司有固定的候选人推荐报告模板吗？有的话发我一份成品（空白的最好，带 logo 和页脚那种），我照着你们的版式出。

**有模板** → 让他发一份**已经做完的**报告 docx（不是简历），跑：

```bash
python scripts/inspect_template.py --input 他们的模板.docx --logo-dir . --out my-config.json
```

它会扒出页面尺寸、页边距、页眉页脚距离、字体字号、条目符号、页脚保密声明，并把页眉 logo 导出来。产出的 `layout` 段直接就是 config 的一部分，之后所有报告都按他们的版式走。

扒不到的两项（制表位、条目符号）走默认值——抬头或日期列对不齐时，手调 config 里的 `tab_field_cm / tab_edu_cm / tab_job_cm` 三个数就行。

**没有模板** → 用内置版式（A4、宋体五号、■ 条目、0.74cm 悬挂缩进），跳过 inspect 这步，config 里只填公司名和页脚声明。

## 一、开工前先要三样（JD 要不到就降级）

**能拿到 JD 就对着 JD 写，拿不到就按简历综合总结。**

先要到：

1. **职位名**——照抄客户 JD 的岗位名，别自己改写。（必填，没有就写不了）
2. **客户公司**——推多家时可以不填，报告里写「—」。
3. **岗位介绍 / JD 原文**——职责和要求那一段，越全越好。

要的句式（直接发给业务方或客户）：

> 这个岗麻烦给我三样：职位全称、客户公司名、岗位介绍（职责和要求那块原文发我就行）。
> 推荐理由我要按职责一条条对着写，不然写出来是空的。

**用户手上没有 JD 怎么办**：别卡着不动。照样出报告，推荐理由改成综合总结——按「能力结构 + 最硬的两段经历 + 一个可验证的数字」写，别硬凑方向。同时在对话里说一句「这次没 JD，我是按简历综合写的，等拿到岗位介绍我再对着改一版」。

### 有 JD 时：拆成对应的几条

推荐理由 **3–5 条**，条数跟着 JD 的职责走：JD 只有三块就给三条，五块就给五条。别硬凑，也别把两条挤成一条。

拆法：

- 把 JD 的「职责」列出来，通常 3–5 条 → 表面上是几种能力。
- 挑出**最不像通用要求**的那一条（「端到端深度学习选股」「Level-2 逐笔因子」「应届生有同行实习经验即可」），那才是这家真正卡人的点。
- **第一条理由压在这一点上**，后面几条顺着客户的次要关切排。

落笔前先把这张表写出来给用户看一眼，再写理由：

| JD 要的 | 候选人哪件事对上 | 落到第几条理由 |
| --- | --- | --- |
| 端到端深度学习选股 | TikTok 双塔召回 + ICLR 二作 | 第一条 |
| 因子合成 | 200 余因子库、rIC 16.7 | 第二条 |
| 快速上手 | 已在上海、可即刻到岗 | 第三条 |

对不上的地方老实留着——那是面试要问的，不是报告要藏的。

### 没 JD 时：综合总结

按这个顺序铺开，凑够 3–5 条：

1. **学历与专业**（学校 + 学位 + GPA，一行说完）
2. **最硬的两段经历**（机构名 + 做了什么，别只写机构名）
3. **一个可验证的量化结果**（R²、准确率、IC、规模、排名，挑最漂亮的那个）
4. **技术栈或工程能力**（能把模型跑进生产的那部分）
5. **一个加分项**（奖项、开源、资格证书、可即刻到岗）

五条比三条更能撑住一页，也更容易让客户找到他自己关心的那条。

### 公司信息：一份 config，换公司只改这里

logo、页眉公司名、页脚保密声明都在 `examples/config.example.json`，脚本和版式不用动：

- **logo 留空** → 页眉显示 `company` 的文字；`company` 也留空 → 页眉就是空的。
- 页脚保密声明是通用文案，「我司」指发件方，换成哪家公司都成立。
- 这个 skill 本身不绑任何公司。同行拿去，改这三行就能用。

## 三、内容规范（比版式重要）

### 推荐理由

- **3–5 条**（脚本最多放 5 条），每条压到**一行**（约 42 个全角字符以内）。超了就会折行，版式立刻散。宁可从五条里砍掉一条，也不要让某条折成两行。
- **对着客户的 JD 逐条写**，不要泛泛写资历。JD 要因子合成 → 第一条就写因子；JD 要低延迟 → 第一条就写延迟和吞吐。
- **正式书面语**。不写「摸过」「这一套」「三条线都在自己手上」这类口语。
- 每条带一个可验证的事实或数字（年限、规模、指标、排名），不写「能力强」「有责任心」。
- 顺序：能力最贴 JD 的在前，可到岗/在本地这种决策信息放最后一条。

### 基本信息

- 缺的项写「—」，**不要编**。最常缺的是：出生年月、家庭地址、专业资质、手机、邮箱。
- 简历里没有手机邮箱时，在交付说明里点出来让用户补。

### 技能

- 三到四行，每行一行放得下（约 45 字符）。
- 固定开头：`语言：` / `研究：` / `工具：` / `专长：`，冒号后接顿号分隔的清单，结尾分号。
- 技术栈写在「工具」，方法论写在「研究」，别混。

### 工作经历

- 每段：一行「日期 + 公司，职位」，一行「主要职责与业绩：」，下接 2–4 条 `■ 标签：内容`。
- **每条 bullet 压到 3–4 行**。简历原文常常一条七八行，必须砍：留数字、留方法名、留动作，砍掉铺垫。
- 标签用两到四个字概括这一条在干什么（组合管理 / 因子体系 / 指数增强 / 系统建设），客户扫一眼就知道结构。
- 每段工作经验最多 3 条 bullet。第四条的边际价值远低于它带来的分页风险。
- 时间必须连续可解释。有重叠、有空窗，交报告之前先问清楚，别自己圆。

### 别写进报告的东西

- 薪水、期望涨幅、竞业细节（这些在推荐评语或电话里说，不落纸）。
- 候选人的健康、家庭、情绪。
- 简历里明显可疑的数字（「实盘 2 亿、单月 6 倍」这类）先验真再写。

## 四、版式（脚本里已经固定，改常量即可）

| 项 | 值 |
| --- | --- |
| 页面 | A4，边距左 3.17 / 右 3.01 / 上下 2.54cm |
| 正文字体 | 中文宋体 + 西文 Calibri，10.5pt（五号） |
| 行距 | 单倍（不要设固定值，会挤成一张） |
| 条目符号 | `■`（U+25A0）。**不要用 `⚫`**，多数字体没有这个字形，渲染会变成黑块 |
| 字段对齐 | 制表位：字段值 5.3cm、学校名 4.46cm、公司名 5.47cm |
| 悬挂缩进 | 0.74cm（`■` 那一行凸出，续行对齐正文） |
| 分页 | 小标题 `keep_with_next`、bullet `keep_together`，防止标题落单和句子被切断 |
| 页数 | **两页**。超过两页就要砍内容，不是缩字号 |

## 五、生成

```bash
pip install python-docx
python scripts/report.py --config my-config.json --data 张三.json --out 张三-XX基金-量化研究员.docx
```

`data.json` 的字段见 `examples/data.example.json`。

生成后**一定要渲染出来看**，别只看 docx 有没有报错：

```bash
soffice --headless --convert-to pdf --outdir ./out 报告.docx
pdftoppm -png -r 144 ./out/报告.pdf ./out/page
```

Windows 上把 `soffice` 换成 LibreOffice 安装路径里的 `soffice.exe`；装了 office-render 之类的 skill 也可以直接调。

看三件事：**有没有折行**（一行变两行立刻发现）、**两页怎么分**、**第 2 页是不是只剩一两行**（那是排版事故）。

## 六、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 某个字被挤到下一行 | 那一条超了一行宽度 | 删掉「并」「也」「方面」这类虚词，或把数字换成更短的写法 |
| 第 1 页底部空一大块 | 下一段是「公司+职位+label+bullet」整块，放不下就整体跳页 | 减一个空行，或把那条 bullet 压掉一行 |
| 第 2 页只剩半段 | 内容总量刚过 1 页 | 砍 bullet 到 2 条，或把所有 bullet 各压一行，试着塞进 1 页 |
| 文件存不下来 | Word / WPS 正开着这个文件 | 脚本会自动改存 `-v2`，关掉再重命名 |
| 打开显示乱码或方框 | 目标机器没有宋体 | 换「思源宋体」等开源字体，改 `EAST_FONT` |

## 七、交付时说什么

报告给出去的时候，顺手说三件用户可能没注意到的事：

1. 哪几项是「—」（简历里没有，需要他补）。
2. 这份简历里最经不起追问的一点（时间重叠、没有数字、年限不够）。
3. 推荐理由是对着哪个 JD 写的——换客户时哪一条要改。
